# More abilities

**Purpose.** Read this when a Legend class needs an ability the game doc does not give it (every MVP class is one ability short of "3 abilities plus an ultimate", see `../game-design/06-abilities-and-progression.md` and `discrepancies.md` DISC-19), when you want a second ultimate to offer as a loadout choice, or when a status effect named in the sources (bleed, concussion, crushed, enraged, ...) needs a duration and a stacking rule before it can be a `StatusEffectDefinition`. Everything here is a proposal for the product owner (`README.md` explains how one is accepted); the recommended third ability per class is the one `balancing.md` already prices. Tone target is the game doc's grand dark fantasy: names must read on a gold-and-white paladin and on a lava-and-rock hellknight alike.

Conventions: every ability card gives a one-line effect, its damage type, the loadout-configurable **varieties** (the game doc's pattern: Imbue has Damage/Support, Blade Runner has Physical/Magical), the **counterplay** a reader can verify in play, and the `AbilityEffect` strategies it **composes** (§1). Numbers are `Recommendation:` unless marked `TUNE` with a source; the priced values for the recommended picks live in `balancing.md` and are not repeated here. Item status of every row: proposed. MVP status is per row.

## 1. The `AbilityEffect` catalogue these proposals compose

The architecture (`../../architecture/05-abilities-weapons-and-loadouts.md`, `../../architecture/02-code-structure.md` §9) builds an ability from a content definition plus a list of effect strategies resolved through the `AbilityRegistry`. The requirements doc's test is that adding an ability is "extremely simple"; the litmus test is that a new ability that only recombines existing effects is **content only**. Every proposal below is expressed against this catalogue so the reviewer can see which ones need a new class (`Recommendation:` the ten below plus one):

| Effect kind  | Class (`abilities/effects/`) | What it does                                                                                               | Key parameters (content)                                          |
| ------------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `damage`     | `DamageEffect`               | Instant damage to every target in a shape through the `DamagePipeline`                                     | `amount`, `damageType`, `shape`, `structureMultiplier`            |
| `heal`       | `HealEffect`                 | Restores base health to allied targets in a shape                                                          | `amount` or `fractionOfMax`, `shape`                              |
| `buff`       | `BuffEffect`                 | Applies a positive `StatusEffectDefinition` to allies (or self)                                            | `statusId`, `durationSeconds`, `stacks`, `shape`                  |
| `debuff`     | `DebuffEffect`               | Applies a negative `StatusEffectDefinition` to enemies                                                     | `statusId`, `durationSeconds`, `stacks`, `shape`                  |
| `dash`       | `DashEffect`                 | Moves the caster along a vector with swept collision; optional `teleport` flag; collects units in the path | `distance`, `durationTicks`, `teleport`, `onPath` (child effects) |
| `knockback`  | `KnockbackEffect`            | Impulse away from a point (or `knockup`: impulse plus the `airborne` status) scaled by mass                | `impulse`, `knockup`, `shape`                                     |
| `zone`       | `ZoneEffect`                 | Spawns a `Zone` entity with a lifetime that applies child effects to units inside each tick or on entry    | `shape`, `lifetimeSeconds`, `everyTicks`, `onTick`, `onEnter`     |
| `projectile` | `ProjectileEffect`           | Spawns a pooled `Projectile` with child effects on hit; pierce or burst                                    | `speed`, `radius`, `range`, `pierce`, `onHit`                     |
| `summon`     | `SummonEffect`               | Spawns entities from a definition, owned by the caster, with a lifetime and a `RemovalCause` of `expired`  | `definitionId`, `count`, `lifetimeSeconds`, `controllerId`        |
| `reveal`     | `RevealEffect`               | Grants allied `Vision` over an area or marks targets so allies see them                                    | `shape`, `durationSeconds`, `markStatusId`                        |
| `revive`     | `ReviveEffect`               | Returns an intact allied corpse to play at a health fraction (the Magus default action needs it anyway)    | `healthFraction`, `corpseMaxAgeSeconds`, `reviveLockoutSeconds`   |

`revive` is the eleventh kind, added because Revive is already **MVP** as the Magus default action and "Last Rites" (§4) reuses it. A definition lists `effects` in order; a **variety** is a partial override of that list (a different `statusId`, an extra child effect), so varieties are content only. **Restrictions** (`abilities/restrictions/*Restriction.ts`: `not-while-carrying`, `requires-target`, `not-in-enemy-aura`, ...) are predicates the `AbilityRuntime` evaluates before the cost is paid. Sketch (not code that exists):

```ts
// packages/core/src/content/abilities/hamstring.ts (sketch)
export const HAMSTRING = {
  id: 'hamstring',
  displayName: 'Hamstring',
  classId: 'warrior',
  slot: 'ability', // 'ability' | 'ultimate' | 'default-action' | 'passive'
  cooldownSeconds: 9, // TUNE: Recommendation in balancing.md
  aetherCost: 25, // TUNE: Recommendation in balancing.md
  targeting: { kind: 'aimed', range: 12 },
  effects: [
    {
      kind: 'projectile',
      speed: 30,
      radius: 0.2,
      onHit: [
        { kind: 'damage', amount: 80, damageType: 'physical' },
        { kind: 'debuff', statusId: 'bleed', stacks: 1 },
        { kind: 'debuff', statusId: 'slowed', durationSeconds: 1.5 },
      ],
    },
  ],
  varieties: {
    serrated: { effects: [{ path: [0, 'onHit', 1], stacks: 2 }] },
    hooked: { effects: [{ path: [0, 'onHit'], append: { kind: 'debuff', statusId: 'pulled' } }] },
  },
  restrictions: ['not-while-carrying'],
  scaling: { amount: { perLevel: 0.04 } },
} satisfies AbilityDefinition;
```

Single place of change (OCP): a new ability that recombines these kinds is one content file plus a catalogue line; a new effect kind is one `<Kind>Effect` class plus one `defaultAbilityRegistry.ts` line; nothing in `AbilitySystem` changes.

## 7. Proposed status effects

Every status in the sources and in the proposals above, with the semantics a `StatusEffectDefinition` needs. Stacking modes (`Recommendation:`): **refresh** (reapplying resets the duration, nothing else), **intensity** (each application adds a stack up to `maxStacks` and refreshes the duration), **duration** (each application adds time up to a cap), **independent** (each source keeps its own timer), **permanent** (no duration; removed only by an explicit event). Hard control (stun, knockup, pulled, taunted) is followed by `control-immune` for 0.5 s so chains cannot lock a unit forever; bosses and the Eternal form multiply control durations by their `controlResistance` (0.25 per `balancing.md`; the game doc only says "knockback/stun reduction") instead of ignoring them. Structures ignore every row except burn (at the structure multiplier) and the shield-related ones. All magnitudes are `Recommendation:` unless a source is named.

## 8. Engineering notes

- Definitions live in `packages/core/src/content/abilities/<id>.ts` and `content/status-effects/<id>.ts`; the `StatusEffectSystem` reads `stacking`, `maxStacks` and `durationTicks` from the definition and never branches on an ID. A new stacking mode is a union member plus one `case` in `StatusEffectRuntime` (OCP); a new status is content only.
- Composition over subclassing (D4): no ability is a class. `AbilitySystem` iterates ready runtimes, evaluates restrictions, pays aether, and runs `effects` in order through the registry; effects call component methods (`Health.applyDamage`, `Movement.applyImpulse`, `StatusEffects.apply`), never each other (SRP, rule 12).
- Deterministic and replayable by construction: effects use tick counts and the seeded `Rng`; Mirror of Ash and Wraithcall spawn through `EntityFactory` with a lifetime, so their removal carries `RemovalCause: 'expired'` and the "despawn without a remover" invariant stays satisfied (`discrepancies.md` DISC-47).
- Team changes in Raise Dead go through `Team.setTeam` and emit `team-changed` (D10), never re-instantiation.
- Invariants worth adding when these ship: a status never exceeds `maxStacks`; `control-immune` is present for the tick after any hard control expires; a zone's lifetime is finite; a summoned unit dies with its owner or its timer.
- Balancing: cooldowns, aether and magnitudes for the recommended picks are in `balancing.md` ("Aether costs and cooldowns"); every other number here is a starting point for the same soak harness.
