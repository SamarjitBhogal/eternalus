# Discrepancies

**Purpose.** Read this when the requirements doc ("the bible") and the game doc (Eternalus v2) say different things, when either of them disagrees with the repo as it stands (the scaffold on `main`, the `feat/map` branch, `CONTRIBUTING.md`) or with a Phase 0 doc, or when you are about to implement a rule that a teammate remembers differently. Each row names the conflict, where it lives, the proposed resolution and its status. `decided` rows cite the brief decision (D1–D12), the reference doc that settled the reading, or the engineering rule that makes the question moot; `open` rows need the product owner and are collected at the end for `INBOX.md` (DEC-09 already points here). Design questions that are not conflicts live in `../game-design/12-open-questions.md` (OQ-nn); a row here that is also an OQ says so.

## How to read the table

- **ID** is stable; never renumber (other docs cite these IDs: `balancing.md` cites DISC-07, 09, 10, 11, 19, 21, 22 and 43). Append new rows at the end of the last section.
- **Where** names the source section (game doc sections as in `../source/game-project-eternalus-v2.md`; requirements doc as in `../../requirements/source/requirements-of-architecture.md`) or the repo path.
- **Status**: `decided (Dn)` = settled by the brief and an ADR; `decided (reading)` = the reference docs adopted one reading and no one has objected; `decided (engineering)` = a code rule makes the conflict disappear; `open` = the product owner must choose; `pending` = a doc or scaffold fix that is already agreed and just has to be done.
- **Owner?** = whether the product owner still has to say something. Proposed resolutions are `Recommendation:` unless a decision is cited.
