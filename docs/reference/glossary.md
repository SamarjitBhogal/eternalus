# Glossary

**Purpose.** Read this when a term in any doc is unfamiliar, before naming a class, a content id, an event or a branch, and when two teammates use different words for the same thing. It is the canonical vocabulary from the writer brief (§2): the game terms come from the requirements doc and the game doc (with the spelling and code names the reference docs adopted, for example **horde**, never "hoard"), the engineering terms from the architecture docs and the agent harness. Game terms and engineering terms are mixed in one alphabetical list on purpose, because code and design share one vocabulary. Display names still pending are marked "(rename pending)" and their proposals live in `suggestions/naming.md`.

## Conventions

- **Code name** is the class, type, file or content id to use in code, tests, events and commit messages. Classes are `PascalCase`, content ids and event/command names are `kebab-case`, constants `SCREAMING_SNAKE_CASE` (`CONTRIBUTING.md` §2). A code name marked "(proposed)" comes from a suggestion doc and does not exist in the architecture docs yet.
- Paths are relative to `packages/core/src/` unless they start with `apps/client/src/`, `docs/` or a root file name.
- "MVP status" of a term is not repeated here; it lives in `game-design/11-mvp-scope.md`. The brief decisions are cited as D1–D12.

| D1–D12                         | The twelve decisions in the writer brief (TypeScript everywhere, React + Redux, IndexedDB facade, entity model, phase branches, docs tree, generated map, single thread, 30 TPS, team as property, sub-classes as data, post-MVP set).      | `docs/decisions/` (ADRs 0003–0009 for D1–D7, D10, D11; architecture docs for D8, D9; the plan backlog for D12) |
