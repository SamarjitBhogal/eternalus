# Figma frames and creative decisions

**Purpose.** Read this before you build, change or visually audit a selection screen or the HUD.
§1 names the owner's Figma frames that are the visual design, §2 the rules for registering a
difference between the build and a frame, §3 the register of every difference made on purpose,
so that a visual audit flags only real defects, §4 the regions each rendering floor covers, with
their numbers, and §5 the two contrast sets of CD-21; the appendix lists the build rulings (OD
ids) the rows cite. The decisions behind it are DEC-48 to DEC-55 in
[13-owner-decisions-log.md](13-owner-decisions-log.md); the screen flow is
[14-interface-and-screen-flow.md](14-interface-and-screen-flow.md).

Rules for every frame:

- A hidden layer (closed eye in Figma) is not part of the design, e.g. the HUD's "Stat Group" and
  "Gadget 2" or the "Reference Image" and "Pedastel Background" layers. Nothing in a hidden layer
  is built or bundled.
- Text and numbers in a frame are sample data. A live match shows only what the game has
  (`INBOX.md` HC-F6); tests and audit scenarios pin the samples so pixels can be compared.
- The frames' class names are display names (DEC-48). The owner renamed two Legends after drawing
  the frames: the Figma's "Cantor" and "Gravecaller" ship as the Legends `oracle` and
  `necromancer`, whose titles are content (`packages/core/src/content/legends/specs/`; DEC-49,
  CD-26).
- Every image is the owner's except the Phosphor Icons placeholders, which are MIT (DEC-51).
  Renders of the frames made on the scratch page of his file (DEC-54) are his art too.
- The frames bind no Figma variables; every colour is a token in
  `apps/client/src/styles/global.css` ([13-game-interface §7](../../architecture/13-game-interface.md#7-styling-accessibility-and-react-rules)).
- Two data switches keep a Figma-exact path and an alternative live side by side: `effectsRenderer`
  (`'figma-raster'` by default, or `'css'`; DEC-54, CD-27) for the selection screens' GLASS, halo
  and button-chrome effects, and `contrastMode` (`'figma'` by default, or `'minimums'`; DEC-55,
  CD-21) for the HUD colours below the contrast minimums of architecture 13 §7. A later creative
  variant uses the same pattern (DEC-53).

## 2. Registering a difference

A built screen matches its frame pixel for pixel at 1920 × 1080 and device pixel ratio 1, except
where a row in §3 says otherwise. A row has one or two of these kinds:

| Kind            | When                                                                                                                                               | What must exist                                                                                                                           | Audit treatment                                                                                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `forced`        | A binding rule requires the difference (`AGENTS.md`, an architecture doc, a requirement, an owner decision).                                       | The citation.                                                                                                                             | A mask over the difference only, or none if the frame's state hides it.                                                                                           |
| `fill-in`       | The frame draws no such state (focus, hover, pressed, disabled, locked, cooldown, no data).                                                        | The rule that needs the state, if any.                                                                                                    | Not visible in the frame's state; the owner reviews it.                                                                                                           |
| `approximation` | A Figma effect that CSS cannot render exactly (GLASS, layer blur, noise).                                                                          | The Figma's own pixels where a render of the frame is drawn.                                                                              | Where the Figma's render is drawn, audited like the frame; an approximation is reported beside it and masked only if its row says so.                             |
| `normalised`    | A sub-pixel simplification below the audit's floor.                                                                                                | The measured size of the difference.                                                                                                      | None expected; a failing region is fixed, never masked.                                                                                                           |
| `conflict`      | A Figma value that breaks a binding minimum, for example a contrast ratio.                                                                         | The minimum and the measured value.                                                                                                       | Built as drawn until the owner rules; the alternative the ruling selects is reviewed.                                                                             |
| `creative`      | An improvement on the frame (DEC-53).                                                                                                              | The frame's original as a live, selectable variant, chosen by data.                                                                       | The audit runs the original variant, unmasked.                                                                                                                    |
| `floor`         | A rendering-engine difference that no code value can reach: Chrome and Figma rasterise glyph edges, glows or a fractional text origin differently. | The rule that defines the floor (OD-18, OD-21, OD-25, OD-27, OD-29), quoted in the row, the regions it covers and their measured numbers. | Reported with its numbers on every audit, never blocking and never masked. A region outside the row's limits is a defect unless the row names it as an exception. |

Rules:

1. The change that introduces a visible difference adds its row in the same pull request. Ids are
   `CD-nn`, never reused or renumbered; a withdrawn row stays, with status `withdrawn`.
2. A visual-audit mask cites its row in its reason: `creative-decision CD-nn: <one line>`. A mask
   with no row, or larger than its row's box, is a defect.
3. A `creative` original is never commented-out code: the original and the improvement are both
   live, both rendered by tests, and one data value chooses between them
   ([13-game-interface §9](../../architecture/13-game-interface.md#9-recipe-a-screen-a-hud-element-an-action)).
4. A row whose rule is a default the owner has not ruled on names its `INBOX.md` item; the row
   changes if he vetoes the default.
5. New rows reach the owner through the pull request's `INBOX.md` item (HC-C1 for the rows below).
   A difference from the architecture docs, as opposed to a frame, goes through the pre-PR gate
   instead (`AGENTS.md`: violation, acceptable, or better than the design).
6. Not differences, so never registered as rows of their own: sample data a scenario pins, text
   rasterisation that keeps the glyphs' position and colour, and anything inside a hidden layer.
   Where such rasterisation still exceeds the audit's general threshold, the region is listed
   once, with its numbers, in §4 under the `floor` row of its kind, so the owner sees it.
7. The `OD-nn` ids the rows cite are build rulings made for this branch by the session that
   coordinated it, not owner decisions; the appendix lists them, and each `floor` row quotes the
   rule it applies.
