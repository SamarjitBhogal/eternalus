# Post-MVP backlog

## Purpose

Read this when someone asks "can we add X?", when you find an idea in the game doc that is not
in [11-mvp-scope.md](../reference/game-design/11-mvp-scope.md), or when a Phase 6 decision cuts
an MVP-if-time item. Every row names the **extension point** the plan already reserves for it,
so that building the MVP keeps the seam open ("new idea? add a new class, a content entry and a
registry line — nothing else changes", the product owner's litmus test) and so that nobody
builds the feature early. Nothing here is in scope until the product owner moves it (see the
last section). The recipes for using each seam live in
[17-extension-recipes.md](../architecture/17-extension-recipes.md); the decisions that put items
here are D11 and D12 in the writer brief and the highlight annotations of the game doc.

## How to read the tables

- **Source / status:** the game doc, the requirements doc or a brief decision, plus the tag
  (**post-MVP**, **MVP-if-time** with its roadmap cut line, `idea-pending`, `needs-planning`,
  **removed**).
- **Extension point:** the seam named in the phase and architecture docs. It is planned or
  already in the code, but the feature is not built; the phase doc that lands it is cited. If a
  seam is missing when the code arrives, that is an architecture bug to fix in the phase, not a
  reason to build the feature.
- **Trigger:** the Phase 6 or later event that opens the row: a `v0.1.0-mvp` follow-up, a
  metric from Phase 6, or a cut decision. `Recommendation:` triggers are the architect's; the
  product owner confirms them at the Phase 6 retrospective.

## How an item leaves the backlog

1. The product owner decides in `INBOX.md` (agents never start a backlog item unprompted).
2. The item's tag changes in [11-mvp-scope.md](../reference/game-design/11-mvp-scope.md) and it
   gets an FR-/NFR- id in [06-mvp-requirements.md](../requirements/06-mvp-requirements.md).
3. A phase doc gains a sprint or task that names the seam from this table, with tests and a
   done-when; [17-extension-recipes.md](../architecture/17-extension-recipes.md) has the recipe.
4. The row is deleted here and the move is logged in [PROGRESS.md](PROGRESS.md).
