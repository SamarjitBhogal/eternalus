# 0009. Config-driven map generation

- Status: accepted (product owner decision, 2026-09-30; DEC-04 on 2026-10-03: `feat/map` is merged into `main` and may be changed to fit this ADR, reviewer Aryan Walanj)
- Date: 2026-09-30

## Context

The requirements document's litmus test: "I should be able to change 3 values in a config
file (NUM_LANES, NUM_SPAWN_TOWERS, NUM_BUFF_TOWERS) and the map would adjust accordingly", and
"minimap should reflect the map changes with no code change needed". A teammate's `feat/map`
branch (2026-09-28) introduces good `MapDefinition`/`MapFeature`/`MapTerrain`/`MapLane` types and
a `MAP_1` constant with lanes, six "team-structure" positions per team, rift and out-of-bounds
polygons hand-traced from the team's sketch at 1600 × 900 world units.

## Decision

- `MapGenerator.generate(config, seed): MapDefinition` is a pure function (a `MapBuilder`
  inside) that places strongholds, lanes, per-lane structures at parametric positions, wall
  rings with gates at lane exits and turrets at vertices, camps between lanes, capture points
  (middle lane = Cathedral), rift and bounds, and scattered obstacles, symmetric about the
  centre. All counts come from `GameConfig.map`.
- Authored data such as the traced Map 1 shapes may exist as a **preset** consumed by the
  generator (overrides for rift/bounds polygons and lane curvature), but a preset must still
  honour every config count; a preset that hardcodes structure positions is rejected.
- `MapFeatureKind` is specific (`spawner-tower`, `buff-tower`, `stronghold`, `wall-segment`,
  `gate`, `turret`, `camp`, `capture-point`, `cathedral`, `corner-camp`, `obstacle`), never a
  generic `team-structure`; `TeamId` lives in a shared teams module, not in map types.
- The minimap is a second projection of the same scene through the same `ViewRegistry`, with a
  `minimapGlyph` per definition, so new features appear on it by construction.

## Consequences

- Tests: mirror symmetry; `numLanes` 3 → 5 regenerates lanes, towers, camps and capture points;
  a feature added in config appears in minimap draw calls with no code change.
- The `feat/map` PR keeps its types (extended) and its polygons as a preset; `MAP_1`'s
  hardcoded positions are replaced by generator output in Phase 1.3
  (`docs/architecture/06-map-and-minimap.md` review notes).
- Destructible terrain updates flow into the runtime `WorldMap` (walkability/cost grids and
  flow fields), never back into the definition.
